How to write a description
  • Write it the way the dataset does: “lines containing …”, “lines that start with …”, “lines with a vowel before a digit”.
  • For a literal word, use one of the four stand-ins the dataset uses: 'dog', 'truck', 'ring', 'lake'. The model has never seen other literals.
  • Regexes match the whole line. The dialect adds & (and) and ~ (not), which ordinary regex engines do not have, so the tester below uses our own matcher.
  • It is a small model trained on about 8,000 sentences: unusual wording, negation and grouping are where it fails.

How this website works

  • No server. The two trained models (1.4M and 1.0M parameters) are downloaded once and run in your browser, in plain JavaScript written for this project. Nothing you type leaves your computer.
  • Same answers as PyTorch. The JavaScript inference was checked against the original PyTorch models on all 999 test sentences: identical output for every one, for both models.
  • Our own regex matcher. The dataset’s regex dialect has intersection (&) and complement (~), so a matcher was written for it and checked against the Python one on over 23,000 (regex, string) pairs.
  • Model. Embedding (128), one LSTM layer (256), a linear and tanh bridge, then an LSTM decoder with additive attention over the input words. Greedy decoding, stopping at the end token.
  • Data. NL-RX-Turk (Locascio et al., 2016): 10,000 crowd-written descriptions paired with regexes, split 8,001 / 999 / 999. The best model also trains on the templated descriptions of the training regexes.

Run the Python code

pip install torch matplotlib        # the dataset is already inside the zip
python src/train.py --name lstm_attn --attention      # train
python src/evaluate.py results/lstm_attn --beam 5     # evaluate
python src/demo.py --run results/lstm_attn            # terminal demo

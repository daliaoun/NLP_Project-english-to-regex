      How to write a description
      • Put literal text in quotes: 'cat', "2024", 'ice cream'. Any word works: the model treats it as a slot and copies it into the regex.
      • It understands contains, starts with, ends with, is exactly, at least or fewer than N times, N times in a row, before, immediately followed by, length (at least, at most, exactly), made only of, and the words not, and, or.
      • Character types: digit (number), letter, capital (uppercase), lowercase, vowel, space.
      • A regex must match the whole line. The dialect adds & (and) and ~ (not), which ordinary regex engines lack, so the tester uses our own matcher.

      How well it works

      Three test sets, none of whose regexes was used for training. New regexes: new combinations in the training style. New phrasings: sentence patterns held out of training. Handwritten: 50 descriptions written by hand. “Same behaviour” means the regex accepts and rejects exactly the same 600 probe strings as the reference.

      How this website works

      • No server. The two trained models (1.38M and 0.96M parameters) are downloaded once and run in plain JavaScript written for this project.
      • Same answers as PyTorch. The browser models were checked against the PyTorch models on all 3,434 test sentences: identical output for every one.
      • Our own regex matcher. The dialect has intersection & and complement ~; the matcher was checked against the Python one on about 3 million (regex, string) pairs.
      • Literal slots. Quoted words become __w0__, __w1__ before the model sees them and are copied back afterwards, so any word works.
      • Data. VeriRegex, generated for this project: every label is checked against an independent Python definition on about 300 strings.

Exact match is strict, so we also test behaviour

Exact match

The generated string is identical to the reference. Strict: equivalent regexes written differently count as wrong.

Functional accuracy

Same behaviour: same accept and reject decisions as the reference on about 600 probe strings, using our own matcher for the & and ~ operators.

BLEU-4

N-gram overlap on regex tokens. Smooth, so it rewards near misses.

Perplexity and token accuracy

Teacher-forced diagnostics that compare models independently of decoding.

Three test sets: new regexes in the training style, 11 held-out phrasing patterns, and 50 handwritten descriptions. The last two measure what a template-trained model cannot simply memorise.

10 · Evaluation

One metric is not enough for this task. Exact match is the strictest, but many regexes are equivalent while written differently, so we added functional accuracy: a generated regex counts as correct if it accepts and rejects the same probe strings as the reference. Python’s own regex module cannot evaluate the intersection and complement operators of this dataset, so we wrote a small matcher. This is a sampling test, not a proof of equivalence. Because the generator writes one canonical regex per meaning, exact match is meaningful here, and we use the behavioural score as a second view. The key design choice is the three test sets: an in-distribution score alone would say little about a model trained on generated sentences.
